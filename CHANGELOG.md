# Изменения

## 1.2.3 — 2026-09-01

### Експорт session (SCARP_CC)

- На карточке контейнера кнопка **Експорт** и пункт контекстного меню **Експорт session**.
- Воркер `export-session` конвертирует `tdata` → настоящий Telethon SQLite `{phone}.session`
  (через opentele `UseCurrentSession`, не 13-байтовая заглушка) + `{phone}.json` + `{phone}.zip`.
- Профиль (`user_id`, имена, username, phone) берётся из `client.get_me()` после подключения.
- Telegram контейнера должен быть остановлен; `automation.lock` как у чистки
  (`AUTH_KEY_DUPLICATED`).
- `2FA.txt` пишется только если пароль передан (`--twofa`); в контейнере 2FA не хранится.
- Прокси контейнера в JSON — строка PySocks-кортежа session-shop / Telegradd
  (`[2, host, port, true, user, pass]`) либо `null`.

## 1.2.2 — 2026-09-01

### Исправления

- **Командная строка процессов не читалась.** `NtQueryInformationProcess` вызывался
  с классом 70 (`ProcessInPrivate`) вместо 60 (`ProcessCommandLineInformation`).
  Из‑за этого matching по `-workdir` никогда не работал: статус/Стоп опирались
  только на `telegram.pid`.
- **Стоп по pid-файлу мог убить чужой процесс.** После выхода Telegram PID
  переиспользуется. Теперь дерево из pid-файла берётся только если процесс —
  `telegram*`/`proxychains*`, а командная строка (если доступна) содержит workdir.
- **Лок чистки снимался до смерти воркера.** «Стоп» на задаче сразу удалял
  `automation.lock` — можно было запустить Telegram, пока Telethon ещё держал
  сессию (`AUTH_KEY_DUPLICATED`). Лок живёт до `Exited`.
- **id контейнера из config.json** мог быть путём (`..\\`, `C:\\…`) — работа и
  удаление уходили за `accounts\\`. Небезопасные id переписываются.
- **Воркер** отказывается стартовать, если `telegram.pid` ещё живой; оборванный
  обход диалогов больше не считается «пустым списком».
- Пароль HTTP/SOCKS прокси в воркер уходит через `TGMANAGER_PROXY_PASS`, не argv.
- HTTP-мост: хост без CR/LF в CONNECT, таймаут рукопожатия 20 с.
- Строка прокси понимает `[IPv6]:port`.
- Журнал задачи не расходился с коллекцией после обрезки на 2000 строк.

## 1.2.1 — 2026-09-01

- Кнопки залипали в состоянии hover после клика по GitHub/Telegram: окно теряло фокус до
  отпускания кнопки, и анимация «отпустили» уводила фон в цвет наведения уже после того,
  как отработал выход из hover. Эффект нажатия вынесен в отдельный слой (`Press`) с
  собственной анимацией 0→N→0; паддинг кнопок перенесён с рамки на содержимое.

## 1.2.0 — 2026-09-01

### Исправления

- **Стоп больше не убивает чужие процессы.** Раньше «наши» процессы искались по подстроке
  `telegram` в имени + командной строке. Если путь к программе содержал слово *telegram*,
  под раздачу попадали `explorer.exe`/`cmd.exe`, открытые в папке контейнера. Теперь
  фильтр только по имени процесса (`telegram*`, `proxychains*`), командная строка читается
  только у них.
- **UI не подвисает при опросе статуса.** Опрос раз в 2 с делал снимок процессов и читал
  командные строки *всех* процессов *для каждой* карточки на UI-потоке. Теперь один снимок
  на опрос, чтение в фоне, командные строки — только у целевых процессов.
- **«Стоп» и удаление контейнера — асинхронно.** `taskkill` + ожидание (до 6 с) больше не
  блокируют окно; на карточке показывается «Остановка…», кнопки заблокированы.
- **Maximize не наезжает на панель задач** и не вылезает за края монитора
  (обработка `WM_GETMINMAXINFO` для окон без рамки). Иконка «развернуть/восстановить»
  обновляется и при двойном клике по заголовку.
- **Прогресс-бар в «неопределённом» режиме** раньше рисовался как статичная полная полоса
  (кастомный шаблон без анимации). Теперь бегущий блик.
- **Прогресс скачивания** Telegram/ProxyChains показывается полосой, журнал не засоряется
  200 строками «↓ 37 %». Обрыв загрузки (скачано меньше Content-Length) считается ошибкой.
- **Журнал задачи живой** и немодальный: строки дописываются по мере работы воркера,
  главное окно не блокируется.
- **Последние строки воркера не теряются.** `Exited` мог приходить раньше хвоста stdout;
  теперь ждём EOF потоков перед завершением задачи.
- **Проверка Python не подвешивает UI повторно** — результат кэшируется; проба проверяет
  наличие `telethon`/`opentele`, а не просто `print(1)`.
- **Повреждённый config.json не затирается.** Копия сохраняется в
  `config.broken-<дата>.json`, пользователю показывается предупреждение. Дубли id и
  пустые поля в конфиге чинятся при загрузке.
- **Удаление контейнера** останавливает идущую чистку и Telegram, ошибку удаления папки
  (занята процессом) показывает вместо тихого игнорирования.
- **Мост HTTP-прокси**: поддержка IPv6 (ATYP 0x04), таймаут подключения к прокси 15 с,
  корректные SOCKS-ответы об ошибке вместо обрыва; при закрытии программы — предупреждение,
  что контейнеры с HTTP-прокси потеряют связь.
- **Строка прокси** понимает схему (`http://`, `socks5://`) и выставляет тип; неверный
  порт — ошибка, а не тихая подмена на 1080.
- **Биндинг `ProgressBar.Value`** на read-only свойство задачи сделан `OneWay`
  (двусторонний биндинг на свойство без сеттера падает в рантайме).
- Защита от бесконечной рекурсии при обходе дерева процессов (переиспользование pid).
- Воркер: понятная ошибка, если не удалось подключиться к Telegram через прокси.
- Необработанные исключения пишутся в `error.log` рядом с программой.

### Интерфейс и анимации

- Плавное появление окон (fade-in 160 мс), кроссфейд между «Контейнеры» и «Задачи».
- Карточки появляются с лёгким сдвигом снизу.
- Кнопки: плавная смена цвета при наведении/нажатии вместо мгновенной.
- Поля ввода подсвечивают рамку при фокусе; чекбокс с галочкой; стрелка комбобокса
  поворачивается; тултипы со скруглением.
- Выбор цвета карточки — со свотчем цвета.
- Клавиатура: Enter/Esc во всех диалогах, фокус на первом поле.
- Версия в статус-баре берётся из сборки, не захардкожена.
- В заголовке окна — кнопки GitHub (репозиторий) и Telegram (разработчик @yeet17).
- README переписан: скриншоты (`docs/screens/`), бейджи, структура, FAQ.
